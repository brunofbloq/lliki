Review the work completed for the current request and update the project wiki only where project knowledge changed.

1. Read `wiki/tasks/scratchpad.md` when it identifies active local work; otherwise
   start from `wiki/index.md`.
2. Read the active task file and relevant evidence.
3. Record final task outcome and traceable validation evidence in the task.
4. Append a decision only if an architectural or engineering decision was accepted.
5. Append a lesson only for a confirmed, reusable finding.
6. Update maintained documentation only when durable project truth changed.
7. Refresh `wiki/tasks/dashboard.md` when task metadata changed.
8. Reset `wiki/tasks/scratchpad.md` to the inactive template.
9. Do not copy scratchpad history into the completed task.
10. Do not rewrite unrelated files or create timestamp-only edits.
11. Preserve unresolved risks, assumptions, and untested conditions explicitly.
12. Use `lliki` internally for mechanical validation or dashboard refresh when available.
