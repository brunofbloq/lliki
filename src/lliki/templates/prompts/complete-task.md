Review the work completed for the current request and update the project wiki only where project knowledge changed.

1. Read `wiki/tasks/scratchpad.md` when it identifies active local work; otherwise
   start from `wiki/index.md`.
2. Read the active task file and relevant evidence.
3. Keep acceptance criteria stable; do not check boxes off step by step.
4. Record only a concise final result and validation summary in the task.
5. Append a decision only if an architectural or engineering decision was accepted.
6. Append a lesson only for a confirmed, reusable finding.
7. Update maintained documentation only when durable project truth changed.
8. Refresh `wiki/tasks/dashboard.md` when task metadata changed.
9. Reset `wiki/tasks/scratchpad.md` to the inactive template.
10. Do not copy scratchpad history or long evidence dumps into the completed task.
11. Do not rewrite unrelated files or create timestamp-only edits.
12. Preserve unresolved risks, assumptions, and untested conditions explicitly.
13. Use `lliki` internally for mechanical validation or dashboard refresh when available.
